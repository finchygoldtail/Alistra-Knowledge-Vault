# Support Desk

## Purpose
Provide a controlled ticketing system for password and account problems, access changes, upgrades, defects, security concerns, data requests and customer support.

## Ticket Types
- Password, MFA and sign-in support
- New user, role change and account removal
- Software defect or service outage
- Upgrade or feature request
- Security incident or suspected breach
- Privacy/data-subject request
- Data correction, export, retention or deletion request

## Required Fields
Ticket ID, customer/organisation, requester, verified contact, category, priority, affected service/project, description, evidence, owner, status, timestamps, actions, approvals and closure outcome.

## Security Rules
Never request passwords, MFA codes, private keys or full secrets. Verify identity before account recovery or access changes. High-risk role changes require authorised approval. Support staff must only access customer data when necessary and every elevated action must be logged.

## Priorities
- **P1 Critical:** active breach, total outage, widespread data loss or dangerous security failure.
- **P2 High:** major function unavailable, suspected unauthorised access or blocked operations.
- **P3 Normal:** standard defects, account requests and planned changes.
- **P4 Low:** questions, minor improvements and future feature requests.

## Workflow
New → Triage → Awaiting Information/Approval → In Progress → Resolved → Closed. Security and privacy tickets follow their dedicated escalation plans and must not be silently downgraded.

## Reporting
Track response time, resolution time, reopened tickets, recurring causes, overdue privacy requests, incidents by severity and customer satisfaction.
