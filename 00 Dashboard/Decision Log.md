| 2026-08-19 | **`stampUserSession`'s `revokeRefreshTokens` call was signing every user out on their first page refresh, on every role.** `revokeRefreshTokens` is per-uid with no way to spare the caller's own session, so calling it immediately after a genuine sign-in invalidated the token that sign-in had just been issued. The already-issued ID token stayed valid for the rest of its hour, hiding the fault until the next page load, when `accounts:lookup` returned `400 TOKEN_EXPIRED` and the SDK cleared the session. Being server-side it also bypassed the Admin/Super Admin exemption in `useSessionEnforcement`, so signing in as a privileged account did not rule the mechanism out — it produced the identical symptom. Removed the call; it never achieved its purpose anyway, killing the new session alongside the old rather than just the old. Single-session enforcement is unaffected — the `activeSessionToken` comparison was always what delivered the kick.
